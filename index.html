개발용 명세 — 데이터 모델과 계산식

이 프로토타입이 실제로 쓰는 구조입니다. 화면의 모든 숫자는 아래 원본 데이터에서 계산됩니다(하드코딩 없음).

1. 데이터 모델

Account   { id, name, kind: cash|bank|savings|invest|real|etc,
            liquidity: instant|short|mid|low|locked, balance }
Debt      { id, name, kind: loan|card|installment, balance, rate?, dueDay? }
Card      { id, name, dueDay, unpaid(전월사용·결제예정), thisMonth(당월사용), installmentLeft }
Recurring { id, name, flow: in|out, amount, day(1-31), category, accountId }
Txn       { id, date, flow: in|out|transfer, amount, category,
            accountId, method: cash|card, memo }
Goal      { id, name, target, currentRef(계좌·자산 id 또는 net), dueDate }
Snapshot  { yyyymm, assets, debts }   // 월말 확정치 저장

2. 핵심 계산식

총자산      = Σ Account.balance
총부채      = Σ Loan.balance
            + Card.unpaid      (전월 사용 · 결제예정)
            + Card.thisMonth   (당월 사용 · 아직 청구 전)  ← 빠뜨리기 쉬움
            + Card.installBalance
순자산      = 총자산 − 총부채

현금성자산  = Σ Account.balance where liquidity = instant

사용가능자금 = 현금성자산
             − 카드 결제예정액
             − 이번 달 남은 고정지출(카드결제 제외)

이번달 예상잔액(월말 현금)
           = 현금성자산
           + 남은 예정수입
           − 남은 고정지출
           − 남은 변동지출 중 현금·체크 결제분

미래 N개월 예상현금
  cash[0] = 이번달 예상잔액
  cash[n] = cash[n-1] + Σ수입 − Σ고정지출
                      − 카드결제(전월 카드사용 추정)
                      − 할부(잔여 회차가 있을 때만)
                      − 시뮬레이션 지출

3. 반드시 지켜야 할 규칙 세 가지

  • 카드는 이중계산 금지. 카드 결제는 사용 시점에 통장에서 나가지 않습니다. 사용 시점엔 Card.thisMonth와 부채만 증가하고, 결제일에 현금이 나갑니다. 지출 통계는 소비 기준, 현금흐름은 결제 기준으로 분리해 계산하세요.
  • 총자산 ≠ 쓸 수 있는 돈. 유동성 등급을 자산의 필수 속성으로 두고, 사용가능자금은 instant만 집계합니다.
  • 적금 자동이체는 지출이 아니라 이동. 현금흐름에서는 유출이지만 순자산은 변하지 않습니다. 저축률 계산 시 다시 더해줘야 합니다.

4. MVP에서 잘라낼 것 / 남길 것

  • 남길 것: 계좌·자산·부채 수동 등록, 반복거래, 순자산 계산, 월별 스냅샷, 사용가능자금
  • 2차: 카드 결제예정 자동 반영, 미래 현금흐름, 시뮬레이션
  • 후순위: 오픈뱅킹·마이데이터 연동(심사·보안 비용이 큼), OCR, 자동분류

5. 이 프로토타입에서 확인할 것

  • 홈 진입 후 10초 안에 네 가지 질문에 답이 되는지
  • 거래 하나 추가했을 때 순자산·사용가능자금·예상잔액이 동시에 맞게 움직이는지
  • 카드 결제 vs 계좌 결제를 바꿔가며 저장했을 때 결과가 다른지
